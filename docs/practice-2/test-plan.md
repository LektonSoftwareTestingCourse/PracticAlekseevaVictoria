# Тестовый план СМП
## Область тестирования

- **Authorization Service** - проверка авторизации транзакций, статусов карт, лимитов и доступного баланса
- **Card Management Service** - создание, получение, изменение и резервирование данных карт
- **Switch Service** - передача запросов между компонентами системы
- **Gateway Service** - обработка входящих запросов
- **Transaction Logger и Notification Service** - обработка событий и сохранение информации о транзакциях
- **Terminal Simulator и Merchant Simulator** - формирование тестовых операций

Проверяются следующие сценарии:
- создание карты
- выполнение транзакции
- успешная авторизация
- обработка отказов
- взаимодействие сервисов при прохождении транзакции

## Подход к тестированию
Тестирование выполняется по уровням:
1. Smoke тестирование - проверка запуска системы и доступности сервисов
2. Модульное тестирование - проверка отдельных компонентов и бизнес-логики сервисов
3. Функциональное тестирование - проверка соответствия работы сервисов требованиям технических заданий 
4. Интеграционное тестирование - проверка взаимодействия сервисов через API и RabbitMQ
5. E2E - проверка полного прохождения транзакции через процессинговую цепочку

Для подготовки тестов используются техники:
- классы эквивалентности
- анализ граничных значений
- попарное тестирование

## Критерии входа

- система развернута и доступна для проверки
- основные сервисы системы доступны и успешно запускаются
- подготовлены тестовые данные
- требования к тестируемой функциональности изучены

## Критерии выхода

- выполнены все запланированные тестовые проверки
- отсутствуют открытые дефекты критического и высокого уровней
- основные сценарии обработки транзакций успешно пройдены
- подготовлены результаты тестирования

## Критерии приостановки и возобновления

- система не запускается
- недоступны критические сервисы
- обнаружены ошибки, блокирующие выполнение основных сценариев

Тестирование возобновляется после устранения причин остановки и восстановления работоспособности системы

## Ресурсы
- тестовая среда СМП
- Docker Compose для запуска сервисов
- технические задания сервисов
- инструменты для проверки API и взаимодействия сервисов
- тестовые данные карт и транзакций

## Расписание
1. Подготовка тестовой среды и проверка доступности сервисов
2. Анализ требований и подготовка тестовых сценариев
3. Выполнение проверок сервисов и взаимодействия между ними
4. Проверка сквозных сценариев обработки транзакций
5. Анализ результатов тестирования

## Риски

Риск 1: Недоступность сервисов

Последствие: Невозможность выполнить проверки

---

Риск 2: Ошибки во взаимодействии сервисов

Последствие: Некорректная обработка транзакций

---

Риск 3: Недостаточное количество тестовых данных

Последствие: Неполная проверка сценариев

---

Риск 4: Ошибки в бизнес логике Authorization или Card Management 

Последствие: Некорректное принятие решений по операциям

## Метрики
- количество выполненных тестовых сценариев
- количество найденных дефектов
- количество закрытых дефектов
- процент успешного прохождения тестов
- покрытие проверяемой функциональности
