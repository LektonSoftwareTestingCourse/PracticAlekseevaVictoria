# Тест дизайн
## Authorization Service
### Классы эквивалентности

**1. Статус карты**

Позитивный класс:
- Карта имеет статус ACTIVE
    - Представитель класса: ACTIVE
    - Результат: проверка карты продолжается

Негативные классы:
- Карта имеет статус INACTIVE
    - Представитель класса: INACTIVE
    - Результат: система возвращает DECLINED с причиной CARD_INACTIVE
- Карта имеет статус BLOCKED
    - Представитель класса: BLOCKED
    - Результат: система возвращает DECLINED с причиной CARD_BLOCKED

- Карта имеет статус EXPIRED
    - Представитель класса: EXPIRED
    - Результат: система возвращает DECLINED с причиной истекшего срока действия карты

**2. Наличие карты**

Позитивный класс:
- Карта существует в системе
    - Представитель класса: PAN существующей карты
    - Результат: обработка транзакции продолжается

Негативный класс:
- Карта отсутствует в системе
    - Представитель класса: PAN, отсутствующий в Card Management Service
    - Результат: система возвращает DECLINED

**3. Срок действия карты**

Позитивный класс:
- Срок действия карты не истек
    - Представитель класса: expiryDate >= текущей даты
    - Результат: проверка продолжается

Негативный класс:
- Срок действия карты истек
    - Представитель класса: expiryDate меньше текущей даты
    - Результат: система возвращает DECLINED с responseCode="54"

**4. Дневной лимит**

Позитивный класс:
- Сумма текущей транзакции не превышает дневной лимит
    - Представитель класса: использованная сумма за день + сумма операции < dailyLimit
    - Результат: проверка продолжается

Негативный класс:
- Сумма текущей транзакции превышает дневной лимит
    - Представитель класса: использованная сумма за день + сумма операции > dailyLimit
    - Результат: система возвращает DECLINED с responseCode="61"

**5. Месячный лимит**

Позитивный класс:
- Сумма операции не превышает месячный лимит
    - Представитель класса: использованная сумма за месяц + сумма операции < monthlyLimit
    - Результат: проверка продолжается

Негативный класс:
- Сумма операции превышает месячный лимит
    - Представитель класса: использованная сумма за месяц + сумма операции > monthlyLimit
    - Результат: система возвращает DECLINED с responseCode="61"

**6.Доступный баланс**

Позитивный класс:
- Баланса достаточно для выполнения операции
    - Представитель класса: amount <= availableBalance
    - Результат: авторизация может быть выполнена

Негативный класс:
- Баланса недостаточно для выполнения операции
    - Представитель класса: amount > availableBalance
    - Результат: система возвращает DECLINED с responseCode="51"

### Анализ граничных значений

**1. DailyLimit**

Проверяется граница между допустимой и недопустимой суммой операций за день

Граница: сумма всех одобренных операций за день + текущая транзакция = dailyLimit.

Тестовые значения:

- OFF (значение ниже границы): dailyLimit-1. Успех
- ON (значение на границе): dailyLimit. Успех
- OFF (значение выше границы): dailyLimit+1. Отказ

**2. MonthlyLimit**

Проверяется граница между допустимой и недопустимой суммой операций за месяц

Граница: сумма всех одобренных операций за месяц + текущая транзакция = monthlyLimit.

Тестовые значения:

- OFF (значение ниже границы): monthlyLimit-1. Успех
- ON (значение на границе): monthlyLimit. Успех
- OFF (значение выше границы): monthlyLimit+1. Отказ

**3. AvailableBalance**

Проверяется граница между достаточным и недостаточным балансом карты.

Граница: сумма транзакции = availableBalance

Тестовые значения:

- OFF (значение ниже границы): availableBalance-1. Успех
- ON (значение на границе): availableBalance. Успех
-  OFF (значение выше границы): availableBalance+1. Отказ

**3. ExpiryDate**

Проверяется граница срока действия карты.

Граница: текущая дата окончания действия карты.

Тестовые значения:

- expiryDate > текущей - успех
- expiryDate = текущей - успех
- expiryDate < текущей - отказ

## Card Management Service

### Классы эквивалентности

**1. Создание карты**

**Поле BIN**

Позитивный класс:
- BIN состоит из 6 цифр и соответствует допустимому формату
  - Представитель класса: 100000

Негативные классы:
- BIN содержит < 6 цифр
  - Представитель класса: 1000
- BIN содержит > 6 цифр
  - Представитель класса: 1000001
- BIN содержит нецифровые символы
  - Представитель класса: ABCDEF

**Поле PAN**

Позитивный класс:
- PAN имеет корректную длину и проходит проверку алгоритмом луна
  - Представитель класса: 4000001234567895

Негативные классы:
- PAN имеет некорректную длину
  - Представитель класса: PAN длиной 15 символов (40000012345678956)
- PAN содержит неверную контрольную цифру
  - Представитель класса: PAN, не проходящий проверку алгоритмом Луна

**Поле expiryDate**

Позитивный класс:
- expiryDate соответствует формату MMYY и содержит будущую дату
  - Представитель класса: 1026

Негативные классы:
- expiryDate имеет неверный формат
  - Представитель класса: 2029
- expiryDate содержит прошедшую дату
  - Представитель класса: 0123
  
**Поле: cardholderName**

Позитивный класс:
- Имя держателя карты заполнено корректно
  - Представитель класса: VIKA ALEKSEEVA

Негативные классы:
- Имя держателя карты отсутствует
  - Представитель класса: пусто
- Имя держателя карты содержит недопустимые символы
  - Представитель класса: 1234

**Поле лимиты карты**

Позитивный класс:
- dailyLimit и monthlyLimit имеют допустимые значения
  - Представитель класса: dailyLimit = 15000000, monthlyLimit = 300000000

Негативные классы:
- dailyLimit имеет отрицательное значение
  - Представитель класса: dailyLimit = -1000
- monthlyLimit имеет отрицательное значение
  - Представитель класса: monthlyLimit = -1000
- Лимиты не переданы при создании карты
  - Представитель класса: отсутствующие значения dailyLimit и monthlyLimit

**2. Получение карты**

Позитивный класс:
- PAN существует в БД
  - Представитель класса: PAN существующей карты

Негативные классы:
- PAN отсутствует в БД
  - Представитель класса: PAN, которого нет в бд
- PAN имеет неверный формат
  - Представитель класса: PAN длиной < 16 символов

**3. Получение списка карт**

Позитивные классы:
- limit и offset имеют допустимые значения
  - - Представитель класса: limit = 50, offset = 0
- Передан существующий статус карты для фильтрации
  -  Представитель класса: status = ACTIVE
- Передан существующий BIN для фильтрации
  - Представитель класса: bin = 400000

Негативные классы:
- limit имеет отрицательное значение
  - Представитель класса: limit = -1
- offset имеет отрицательное значение
  - Представитель класса: offset = -1
- Передан неизвестный статус карты
  - Представитель класса: status = UNKNOWN
- Передан несуществующий BIN
  - Представитель класса: bin = 999999

**4. Обновление карты**

Позитивные классы:
- PAN существует в системе
  - Представитель класса: PAN существующей карты
- Передано корректное значение изменяемого поля
  - Представитель класса: dailyLimit = 20000000

Негативные классы:
- PAN отсутствует в системе
  - Представитель класса: PAN несуществующей карты
- Передано некорректное значение статуса
  - Представитель класса: status = UNKNOWN
- Передано отрицательное значение лимита или баланса
  - Представитель класса: dailyLimit = -1000

**5. Удаление карты**

Позитивный класс:
- PAN существующей карты переводится в статус DELETED
  - Представитель класса: PAN активной карты

Негативные классы:
- PAN отсутствует в системе
  - Представитель класса: PAN несуществующей карты

**6. Генерация тестовых карт**

**Поле count**

Позитивный класс:
- count содержит допустимое количество карт для генерации
  - Представитель класса: count = 100

Негативные классы:
- count = 0
  - Представитель класса: count = 0
- count < 0
  - Представитель класса: count = -1
- count отсутствует
  - Представитель класса: count нет

**Поле BIN**

Позитивный класс:
- Передан список корректных BIN длиной 6 цифр
  - Представитель класса: ["400000", "400001"]

Негативные классы:
- Список BIN пустой
  - Представитель класса: []
- BIN имеет неверный формат
  - Представитель класса: ["40000"]
- BIN содержит нецифровые символы
  - Представитель класса: ["ABCDEF"]

**7. Резервирование средств**

Позитивный класс:
- Сумма резервирования меньше или равна доступному балансу
  -  Представитель класса: amount = 1000, availableBalance = 10000

Негативные классы:
- Сумма резервирования превышает доступный баланс
  - Представитель класса: amount = 15000, availableBalance = 10000
- PAN карты отсутствует в системе
  - Представитель класса: PAN несуществующей карты
- Сумма резервирования имеет отрицательное значение
  - Представитель класса: amount = -1000


### Анализ граничных значений
**1. PAN**

Проверяется граница длины номера карты

Граница:
- длина PAN = 16 символов

Проверяемые значения:
- PAN = 15 символов - значение ниже границы, отклонить
- PAN = 16 символов - значение на границе, принять
- PAN =17 символов - значение выше границы, отклонить

**2. Контрольная цифра PAN**

Проверяется корректность контрольной цифры номера карты

Граница:
- корректность прохождения проверки алгоритмом Луна

Проверяемые значения:
- PAN с корректной контрольной цифрой - успех
- PAN с неверной контрольной цифрой - карта не создается
  
**3. ExpiryDate**

Проверяется формат и срок действия карты

Граница:
- текущая дата окончания действия карты

Проверяемые значения:
- дата < текущей - операция отклоняется
- текущая дата - успех
- дата > текущей - успех

**4. Count при генерации карт**

Проверяется количество создаваемых карт при использовании POST /api/cards/generate

Граница:
- минимально допустимое количество создаваемых карт

Проверяемые значения:
- count = 0 - значение ниже допустимого, генерация не выполняется.
- count = 1 - минимальное допустимое значение, создается одна карта.
- count > 1 - создается указанное количество карт.

## PICT

В модель PICT я передала параметры и значения сервиса, добавила ограничения. В результате PICT сгенерировал сокращенный набор комбинаций (cases.txt и cases-card-management.txt), покрывающий все пары параметров, каждая строка которого соответствует отдельному тест-кейсу.

| ID | Сочетание параметров | Ожидаемый результат |
|-|-|-|
| CRIT-AUTH-01 | card_status=ACTIVE, amount_vs_daily=above, amount_vs_monthly=below, amount_vs_balance=below | DECLINED, превышен дневной лимит |
| CRIT-AUTH-02 | card_status=ACTIVE, amount_vs_daily=below, amount_vs_monthly=above, amount_vs_balance=below | DECLINED, превышен месячный лимит |
| CRIT-AUTH-03 | card_status=ACTIVE, amount_vs_daily=below, amount_vs_monthly=below, amount_vs_balance=above | DECLINED, недостаточно средств |
| CRIT-AUTH-04 | card_status=BLOCKED, amount_vs_daily=below, amount_vs_monthly=below, amount_vs_balance=below | DECLINED, карта заблокирована |
