## Объяснение полученного распределения

**1. Unit**

В новых тестах выделено восемь проверок изолированной бизнес-логики. Они охватывают алгоритм Луна, генерацию PAN, маршрутизацию по BIN, проверку статуса карты, срока действия, лимитов и баланса.

Для проверки логики используются mock-объекты, поэтому тесты выполняются независимо от доступности других сервисов.

**2. API и Integration**

Наибольшая доля приходится на API и интеграционные проверки. Это связано с микросервисной архитектурой СМП: корректность работы зависит от взаимодействия Authorization, Card Management, Switch, PostgreSQL и RabbitMQ.

Особое внимание уделяется сохранению резервирований, доставке транзакций в Logger и передаче карточных событий через Outbox в Notification Service

**3. E2E**

Оставлен один сквозной тест критического сценария: отсутствие подтверждения публикации транзакции и последующий возврат зарезервированных средств

Количество E2E ограничено, поскольку такие тесты требуют запуска всей системы и сложнее в диагностике при ошибках
