# А6. State-transition — диаграмма переходов состояний

## Диаграмма состояний карты и транзакции

```mermaid
flowchart TB
    subgraph CARD["Состояния карты Card.status"]
        NEW["Создание карты"] --> ACTIVE["ACTIVE"]

        UPDATE["PATCH / bulk-update<br/>Изменение статуса"]

        ACTIVE <--> UPDATE
        INACTIVE["INACTIVE"] <--> UPDATE
        BLOCKED["BLOCKED"] <--> UPDATE
        EXPIRED["EXPIRED"] <--> UPDATE

        ACTIVE -->|"DELETE"| DELETED["DELETED"]
        INACTIVE -->|"DELETE"| DELETED
        BLOCKED -->|"DELETE"| DELETED
        EXPIRED -->|"DELETE"| DELETED
    end

    subgraph TX["Состояния транзакции"]
        START["Новая транзакция"]
        START -->|"Авторизация успешна"| APPROVED["APPROVED"]
        START -->|"Проверки не пройдены"| DECLINED["DECLINED"]

        APPROVED -.->|"Rollback резервирования"| ROLLED_BACK["ROLLED_BACK"]
    end

    NOTE["Резервирование средств разрешено<br/>только для ACTIVE-карты"]

    NOTE -.-> ACTIVE

    NOTE2["ROLLED_BACK фактически является<br/>статусом Reservation, а не TransactionStatus"]

    ROLLED_BACK -.-> NOTE2
```

## Чего не хватало

1. В проекте отсутствовала отдельная диаграмма переходов состояний карты.
2. Не были визуализированы состояния транзакции APPROVED, DECLINED и ROLLED_BACK.
3. Не были показаны условия, при которых разрешено резервирование средств.
4. Не было явно разделено состояние транзакции и состояние резервирования.

## Что сделано

- Построена диаграмма состояний карты и транзакции
- Отображены четыре основных статуса карты
- Добавлен переход в DELETED при удалении карты.
- Отображены результаты авторизации APPROVED и DECLINED.
- Добавлен сценарий rollback с переходом резервирования в ROLLED_BACK
