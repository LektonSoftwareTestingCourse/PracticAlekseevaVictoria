# А4. Sequence Diagram — последовательность обработки транзакции

## Диаграмма последовательности

```mermaid
sequenceDiagram
    actor T as Terminal
    participant GW as Gateway
    participant SW as Switch
    participant AUTH as Authorization
    participant CMS as Card Management
    participant BIN as BIN Lookup
    participant DB as PostgreSQL
    participant MA as Merchant Acquirer
    participant RMQ as RabbitMQ
    participant LOG as Transaction Logger
    participant NOTIF as Notification Service

    T->>GW: POST /api/transactions
    GW->>SW: POST /api/internal/route
    SW->>SW: Нормализация запроса и поиск BIN

    alt BIN не найден
        SW->>SW: Формирование DECLINED (14)
    else BIN найден
        SW->>AUTH: POST /api/internal/authorize (0100)
        AUTH->>CMS: GET /api/cards/{pan}
        CMS->>DB: SELECT card
        DB-->>CMS: Данные карты
        CMS-->>AUTH: CardModel

        AUTH->>BIN: GET /api/bin/{bin}
        BIN-->>AUTH: BIN / issuerId

        AUTH->>DB: Проверка и обновление limit_usage
        DB-->>AUTH: Результат проверки

        alt Карта активна, срок действия и лимиты корректны
            AUTH->>CMS: POST /api/cards/{pan}/reserve
            CMS->>DB: Сохранение reservation и обновление баланса
            CMS->>DB: Сохранение outbox_event
            CMS-->>AUTH: Reservation OK

            Note over CMS,RMQ: OutboxProcessor публикует событие асинхронно
            CMS-->>RMQ: card.* 
            RMQ-->>NOTIF: card-notifications
            NOTIF->>DB: Сохранение card_notifications

            AUTH-->>SW: APPROVED (00)
        else Проверка не пройдена
            AUTH-->>SW: DECLINED (причина отказа)
        end

        SW->>MA: POST /api/simulator/merchant/fee
        MA-->>SW: Acquiring fee
    end

    SW-->>RMQ: Publish transaction.log
    RMQ-->>LOG: Queue transaction-log
    LOG->>DB: Сохранение транзакции
    LOG-->>RMQ: Обработка сообщения

    alt Публикация не удалась после APPROVED
        SW->>AUTH: POST /api/internal/rollback
        AUTH->>CMS: POST /api/cards/{pan}/rollback
        CMS->>DB: Сохранение rollback
        CMS->>DB: Возврат средств и изменение reservation
        CMS-->>AUTH: Rollback result
        AUTH-->>SW: RollbackResponse
        SW-->>GW: DECLINED (96)
    else Публикация успешна или транзакция DECLINED
        SW-->>GW: AuthorizationResponse
    end

    GW-->>T: HTTP response
```

## Чего не хватало

1. В исходной документации была только диаграмма успешного сценария.
2. Не был отражен сценарий отказа при проверке карты, баланса и лимитов.
3. Не был показан полный путь резервирования средств.
4. Не была выделена асинхронная обработка через RabbitMQ.
5. Не был отражен сценарий reversal при ошибке публикации транзакции.

## Что сделано

- Добавлен полный сценарий успешной авторизации.
- Добавлена ветка DECLINED с основными причинами отказа.
- Отображено резервирование средств через Card Management.
- Показана асинхронная отправка транзакций в Logger.
- Добавлена обработка карточных событий через Outbox и Notification Service.
- Добавлена ветка rollback при ошибке публикации сообщения.

**Особенность реализации:** в задании reversal обозначен как MTI 0400. В исходном коде есть метод AuthorizationRequest.forReversal(), но он не используется. Фактический откат реализован отдельным запросом POST /api/internal/rollback с объектом RollbackRequest. Это отражено на диаграмме.
